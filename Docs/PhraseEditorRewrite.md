# 詞彙編輯器改寫筆記

2026-07 把詞彙編輯器（PhraseEditor）整個改寫了一輪，這裡記一下前因後果。

## 原本的問題

編輯器打開就顯示「輸入法並未執行」，完全不能用。根本原因是當年從 NSConnection 遷移到 NSXPCConnection 時，新 API 需要 launchd 事先廣告 mach service 名稱，但專案裡沒有任何地方做這件事，所以 server 端 listener 看似啟動成功、實際上收不到任何連線。

而且就算把連線修好，舊架構也撐不住大詞庫：表格每畫一格就要一次同步阻塞的 XPC 呼叫去拿那一列的資料；刪一筆詞是把整張表複製到 temp table 再倒回來（每刪一筆 O(N)）；程式還假設 rowid = 列數 + 1，刪過東西留下 rowid 空洞之後，選哪列改哪列都會錯位。

## 為什麼原本要連線

當年的設計是詞庫 DB 屬於輸入法行程，別人不碰：編輯器要讀寫都請 IME 代勞。另一個原因是新增詞要推導注音得查主辭典，而主辭典當時是加密的，只有 IME 有鑰匙。

## 為什麼現在不需要連線

現在使用者詞庫（`SmartMandarinUserData.db`）和主辭典（`ChiaKeySource.db`）都是明文 SQLite，編輯器自己開就好。真正需要跟運行中的 IME 交流的只剩「編輯器編輯時鎖定輸入法寫表」和「編輯完成解除鎖定」。這種單向、低頻的訊息，用不著連線，檔案加廣播就夠了：

- **editing lock 檔**：編輯器開著就存在並定期刷新 mtime，IME 看到就暫停自己的詞庫寫入（自動學習先跳過、`chiakey://` 加詞先排隊）。設 30 分鐘過期，編輯器 crash 也不會把 IME 卡死。
- **dirty 檔**：每次 commit 就 touch，IME 發現 mtime 變新就重讀語言模型快取。
- **分散式通知**（NSDistributedNotificationCenter）：純粹讓上面兩件事「立刻」發生；漏送也沒關係，IME 每 5 秒輪詢檔案兜底。

順帶一提，偏好設定 app 和 CLI 子命令當年也是走同一條 XPC，一樣壞了，也一併改掉：IME 把模組清單、版本等狀態發布成一個 plist 檔給偏好設定讀，reload 之類的請求用通知送過去。整個專案現在沒有任何 XPC client 了。

## 改寫著重的效能問題

目標是數萬筆詞庫也要順：

- **表格完全虛擬化**：捲到哪查到哪（windowed SQL 分頁 + 頁快取），不再一格一次查詢，開窗、捲動都是即時的。
- **搜尋、排序推給 SQL**：詞用 LIKE、注音轉成 qstring 前綴比對，排序直接 ORDER BY。
- **刪除改用 rowid 定位**：每列 model 自己帶 rowid，批次刪除包成單一 transaction，五萬筆毫秒級。
- **注音推導不做笛卡兒積**：新增詞的預設注音是每個字取最可能讀音；改注音本來就是逐字選，不需要展開所有組合。

兩個要小心的地雷：`user_unigrams` 不能加欄位（IME 的匯入是位置式 INSERT），rowid 只有在「會期內不 VACUUM」的前提下才穩定，所以編輯會期中兩邊都不准 VACUUM。

## 其他

- 注音編解碼改成直接連結 Formosa 函式庫，不再維護一份複製品。
- 匯入匯出完整保留舊 MJSR 格式（含自動學習資料的 hex blob），跟舊版匯出檔互通。
- DB 開檔即設 WAL，IME 讀、編輯器寫可以並行不互擋。
